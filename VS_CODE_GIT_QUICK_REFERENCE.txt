VS CODE GIT - QUICK REFERENCE CARD
===================================

OPENING SOURCE CONTROL:
═══════════════════════
• Mac:    Ctrl + Shift + G  OR  Cmd + Shift + G
• Windows/Linux: Ctrl + Shift + G
• Click: Left sidebar → Branch icon (⎇)


DAILY WORKFLOW (5 Steps):
═════════════════════════

STEP 1: Make changes to your code
        └─ Edit files in VS Code normally

STEP 2: Open Source Control
        └─ Press Ctrl + Shift + G

STEP 3: Stage files (mark them ready)
        └─ Click + next to each file
        └─ Or click + next to "Changes" to stage all

STEP 4: Write commit message
        └─ Click message input field
        └─ Type: "Fixed: Feature X" or "Added: Feature Y"
        └─ Example: "Fixed floor plan camera controls"

STEP 5: Commit + Push
        └─ Click Commit button (✓)
        └─ Click ... → Push to upload to GitHub


SOURCE CONTROL PANEL LAYOUT:
════════════════════════════

┌─ SOURCE CONTROL ─────────────┐
├─ Message input field         ├─ Type commit message here
├─────────────────────────────┤
├─ CHANGES (red files)         ├─ Modified files not yet staged
│  ├─ src/main.ts      [+]     ├─ Click + to stage
│  └─ package.json     [+]     ├─ Click file to see differences
├─────────────────────────────┤
├─ STAGED CHANGES (green)      ├─ Files ready to commit
│  ├─ src/components/  [−]     ├─ Click − to unstage
│  └─ README.md        [−]     ├─
├─────────────────────────────┤
├─ [✓ Commit]  [↻ Discard]     ├─ Buttons to commit or discard
├─ [. . . More Options]        ├─ Click for more Git options
└─────────────────────────────┘


BUTTONS & ICONS:
════════════════

[+]    = STAGE        → Move file to "Staged Changes"
[−]    = UNSTAGE      → Remove from staging
[↻]    = DISCARD      → DELETE changes (Can't undo!)
[✓]    = COMMIT       → Save all staged changes
[...]  = MORE OPTIONS → Push, Pull, Branch, etc.


UNDERSTANDING COLORS:
═════════════════════

RED FILES (Changes section)
└─ Modified but NOT staged yet
└─ Click + to move to staging

GREEN FILES (Staged Changes section)
└─ Ready to commit
└─ Click − to unstage if you changed your mind

WHEN YOU CLICK A FILENAME:
└─ LEFT SIDE (RED) = Old code
└─ RIGHT SIDE (GREEN) = New code


MOST COMMON TASKS:
══════════════════

TASK: See what changed in a file
└─ 1. Click the filename in Source Control
└─ 2. View opens showing differences
└─ 3. Red = removed, Green = added

TASK: Commit all changes
└─ 1. Click ... next to "Changes" or click individual [+]
└─ 2. Type message
└─ 3. Click Commit

TASK: Upload to GitHub for first time
└─ 1. Make your first commit (see above)
└─ 2. Click [...]
└─ 3. Select "Publish to GitHub"
└─ 4. GitHub login page opens
└─ 5. Choose Public/Private
└─ 6. Done! Files upload automatically

TASK: Upload changes after first time
└─ 1. Commit your changes
└─ 2. Click [...]
└─ 3. Select "Push"
└─ 4. Wait for upload

TASK: Download latest changes from team
└─ 1. Click [...]
└─ 2. Select "Pull"
└─ 3. Your files update with latest changes

TASK: See all past commits
└─ 1. Click [...]
└─ 2. Select "Show Log" or "View History"
└─ 3. See all changes ever made

TASK: Create a new branch (for experiments)
└─ 1. Click branch name at BOTTOM LEFT
└─ 2. Select "Create New Branch"
└─ 3. Type branch name: feature/my-feature
└─ 4. Start working!

TASK: Switch back to main branch
└─ 1. Click branch name at BOTTOM LEFT
└─ 2. Select "main"
└─ 3. Done


GOOD COMMIT MESSAGES:
═════════════════════

✅ GOOD EXAMPLES:
   • "Fixed floor plan camera controls"
   • "Added dark mode support"
   • "Updated documentation for API"
   • "Refactored database queries for performance"

❌ BAD EXAMPLES:
   • "stuff"
   • "changes"
   • "fix"
   • "asdfgh"

TIPS:
• Start with action verb: Fixed, Added, Updated, Refactored, Improved
• Be specific about WHAT you changed
• Keep under 50 characters if possible
• No need for period at end

TROUBLESHOOTING:
════════════════

Q: Source Control is empty
A: 1. Click "Initialize Repository"
   2. Or run: git init (in Terminal)

Q: I can't see the Source Control panel
A: 1. Press Ctrl + Shift + G
   2. Or click branch icon (⎇) on left sidebar

Q: Files not showing in Changes
A: 1. Make sure you SAVED the file (Cmd + S)
   2. Or files might be in .gitignore

Q: Can't push (authentication error)
A: 1. GitHub Settings → Developer Settings → Personal Access Tokens
   2. Create token with "repo" permissions
   3. Copy the token
   4. When prompted for password: paste token instead

Q: "Merge conflict" message
A: 1. Click the filename
   2. You see both versions
   3. Click which version you want
   4. Stage and commit the fix

Q: I made a mistake in commit
A: 1. Click [...]
   2. Select "Undo Last Commit"
   3. Your changes go back to Changes section
   4. You can edit and try again
